# 티켓 양식 — 원문과 작성 규칙

이 양식은 **Graph Engineering 의 N2a 파서가 소비하는 것과 같은 양식**이다
(`.claude/skills/graph-engineering/references/jira.md` §2).
여기서 제대로 만든 티켓은 `/graph-run` 이 양식 위반으로 멈추지 않는다.
**작성기와 소비기가 같은 규격을 공유한다** — 그래서 양식을 지키는 것이 형식주의가 아니다.

## 1. 원문

`# 요약` 은 **summary 필드**로, `# 설명` 이하는 **description** 으로 들어간다.

```
# 요약

[repo] 무엇을 어떻게
예: `[cutting-tuna] Swagger 문서를 springdoc-openapi 로 대체`

# 설명

## 대상
- 저장소:
- 모듈/패키지:
- 진입점(아는 만큼):

## 배경
- 현재(As-Is):
- 원하는 상태(To-Be):
- 왜 해야하는가:

## 완료 정의
( ) 조사, 보고까지 ( ) 배포까지

## 참고
- 관련 PR/이슈:
- 관련 티켓:
- 로그, 재현 데이터:

# 요구사항

## 완료 조건
- [ ] (검증 가능한 문장 하나에 하나씩)
- [ ] ...

## 범위 밖 — 이번에 안 하는 것
-

## 제약
- 하위호환: 유지 필요(호출처: ) / 깨도 됨
- DB 스키마 변경: 허용 / 불가
- 성능, 보안: (없으면 "없음")
```

빈 양식은 `.claude/jira/bin/jt template` 로도 얻을 수 있다.

## 2. 항목별 작성 규칙

### `# 요약` — `[repo] 무엇을 어떻게`

- 대괄호 안은 **저장소 이름**. `## 대상 > 저장소` 와 같아야 한다(다르면 경고).
- "무엇을" 만 쓰고 "어떻게" 를 빼지 마라. `[api] 버그 수정` 은 요약이 아니다.
- 255자 제한. 한 줄로 끝낸다.

### `## 대상`

| 항목 | 규칙 |
|---|---|
| 저장소 | **필수.** 비면 차단된다 |
| 모듈/패키지 | 아는 만큼. 비면 경고 — 채우면 영향 범위 조사 비용이 줄어든다 |
| 진입점 | 아는 만큼. 컨트롤러·배치 잡·이벤트 핸들러 등 실행이 시작되는 지점 |

### `## 배경` — 셋 다 필수

- **현재(As-Is)**: 지금 무엇이 어떻게 동작하는가. 관측된 사실을 쓴다.
- **원하는 상태(To-Be)**: 끝나면 무엇이 어떻게 달라지는가.
- **왜 해야하는가**: 안 하면 무엇이 문제인가. **이게 없으면 리뷰가 옳고 그름을 판정할 수 없다.**

### `## 완료 정의` — 정확히 하나

```
(O) 조사, 보고까지  ( ) 배포까지        ← 선택한 쪽 괄호 안에 표시
```

표시는 `O` `o` `v` `V` `x` `X` 아무거나 인식한다. 둘 다 표시하거나 아무것도 표시하지 않으면 차단된다.

### `## 완료 조건` — 최소 1개, 검증 가능하게

```
- [ ] `/api/users/{id}` 가 존재하지 않는 id 에 404 와 에러 코드 USER_NOT_FOUND 를 반환한다
- [ ] 기존 200 응답의 필드 구성이 바뀌지 않는다
```

- **하나의 문장에 하나의 조건.** "A 하고 B 한다" 는 두 줄로 쪼갠다.
- **누가 봐도 참/거짓을 판정할 수 있어야 한다.** "성능을 개선한다" ✗ → "p99 가 300ms 이하" ✓
- 하위 그룹이 필요하면 `### 1. 인증` 같은 헤딩으로 묶어도 된다.
- 이 항목이 비면 그래프도 여기서 멈춘다. **가장 중요한 섹션이다.**

### `## 범위 밖 — 이번에 안 하는 것`

비워둘 수 없다. 정말 없으면 `- 없음` 이라고 **명시**한다.
개발·리뷰에서 **하드 제약**으로 쓰인다 — 여기 적힌 것은 눈에 보여도 손대지 않는다.

### `## 제약` — 셋 다 결정

```
- 하위호환: 유지 필요(호출처: order-service, batch-settlement)
- DB 스키마 변경: 불가
- 성능, 보안: 외부 노출 API 이므로 인증 필수. 없으면 "없음"
```

- 선택지를 **둘 다 남겨두면 차단**된다. 고르지 않은 쪽은 지운다.
- `유지 필요` 면 호출처를 아는 만큼 적는다.
- 제약이 없으면 `없음` 이라고 쓴다. 빈칸은 "안 정했다" 로 읽힌다.

## 3. 검증에서 걸리는 것들

`jt validate --file <초안.md>` 가 판정한다. **차단(violation)** 은 티켓을 만들 수 없다.

| 코드 | 뜻 |
|---|---|
| `SECTION_MISSING` | 필수 섹션이 없다 |
| `TEMPLATE_ECHO` | 템플릿 예시 문구가 그대로 남아 있다 |
| `SUMMARY_FORMAT` | 요약이 `[repo] …` 형식이 아니다 |
| `SUMMARY_PLACEHOLDER` | 요약이 플레이스홀더다 |
| `TARGET_REPO_EMPTY` | 저장소가 비었다 |
| `BACKGROUND_EMPTY` | As-Is / To-Be / 왜 중 빈 것이 있다 |
| `DOD_NOT_CHOSEN` · `DOD_MULTIPLE` | 완료 정의가 0개 또는 2개 선택됐다 |
| `AC_EMPTY` · `AC_PLACEHOLDER` | 완료 조건이 없거나 플레이스홀더다 |
| `OOS_EMPTY` | 범위 밖이 비었다 (`- 없음` 이라도 써야 한다) |
| `CONSTRAINT_EMPTY` · `CONSTRAINT_UNDECIDED` | 제약이 비었거나 선택지가 둘 다 남았다 |

**경고(warning)** 는 차단하지 않지만 사용자에게 보여준다.

| 코드 | 뜻 |
|---|---|
| `TARGET_REPO_MISMATCH` | 요약의 `[repo]` 와 `저장소:` 가 다르다 |
| `TARGET_MODULE_EMPTY` | 모듈/패키지가 비었다 |
| `AC_TOO_SHORT` | 완료 조건이 너무 짧아 검증 가능한지 의심스럽다 |
| `CONSTRAINT_FREEFORM` | 제약이 정해진 선택지가 아닌 자유 서술이다 |
